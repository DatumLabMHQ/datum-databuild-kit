# The Datum dashboard standard

One standard: a Next.js app generated by `bin/datum new dashboard`, reading the Datum data platform through
datum-api, wearing the design system in `templates/dashboard`. The template is itself the reference dashboard.
Run it without a key and it shows the standard look on labelled sample data:

```bash
cd templates/dashboard && npm install && npm run dev
```

Everything below is enforced by the template's components, not by memory. If a rule is not in a component,
put it there.

## 1. The look

One aesthetic, called institutional in the old kit: Inter everywhere including numbers (tabular figures),
sentence case, no uppercase labels or letter spacing, roomy panels with a 12px radius, colour reserved for
data rather than chrome. Light and dark themes flip through tokens; the toggle sits in the topbar.

## 2. Tokens (`app/globals.css`)

Never hardcode a colour, font, radius or spacing. Everything is a CSS variable, and every shadcn/ui variable
(`--background`, `--card`, `--muted-foreground`, `--chart-1`...) is mapped onto the Datum tokens, so shadcn
components and charts wear the Datum look without per-component styling.

| Group | Tokens |
|---|---|
| Surfaces and text | `--bg`, `--bg-2`, `--surface`, `--surface-2`, `--fg`, `--fg-muted`, `--fg-dim`, `--line`, `--line-strong`, `--hover` |
| Accents, each with a `-soft` background | `--orange` (brand), `--green`, `--red`, `--yellow`; plus `--blue`, `--purple`, `--cyan` |
| Brand mark | `--brand-blue` (#4A6CF7): the wordmark accent and nothing else |
| Chart series, in order | `--chart-1` to `--chart-8` |
| Chains, the same in both themes | `--chain-ethereum`, `--chain-base`, `--chain-arbitrum`, `--chain-avalanche`, `--chain-plume`, `--chain-binance`, `--chain-optimism` |
| Shape and depth | `--radius`, `--panel-pad`, `--grid-gap`, `--max`, `--shadow-sm`, `--shadow-md`, `--shadow-lg` |
| Fonts | `--font-sans` (Inter, loaded with next/font), `--font-mono` (JetBrains Mono, for addresses and code only) |

Tailwind utilities work on the same names (`bg-card`, `text-muted-foreground`, `border-border`,
`fill-chart-1`). Plain classes in `globals.css` (`.panel`, `.kpi`, `.datatable`...) carry the layout so pages
stay readable.

## 3. Page anatomy

Every page has the same skeleton, provided by `components/Shell.tsx`:

- **Topbar**: the Datum mark and wordmark, the dashboard title, the navigation, a status pill and the theme
  toggle. The status pill says one of: sample data, platform healthy, platform degraded, platform unreachable.
- **Banner**: shown while the numbers cannot be trusted. Sample data (no key) or draft (brief not signed off).
- **Page header**: `PageHeader` with the title and a subtitle that states the question the page answers and
  the one-line answer with the as-of date. Thesis first, then the numbers.
- **KPI row**: `Kpis` with three to five `Kpi` cards: label, value, optional change with a sign, a sub line.
- **Panels** in `grid-2` / `grid-3` / `grid-4`: see below.
- **Footer**: the provenance line and the as-of date.
- On phones the grids collapse to one column, `.col-hide-sm` table columns drop, and the navigation becomes a
  bottom bar.

## 4. Panels and captions

`Panel` is the only container for a chart or a table. Its `caption` prop is required: one line that says what
the panel shows and why it matters to the page's question, with the first clause in bold. No silent visuals.
`badge` carries the small right-hand note (count, date, a link). `flush` removes the padding for tables.
`note` adds a reconciliation or coverage note under the body.

## 5. Numbers and copy

- Every number goes through `lib/format.ts`: `usd`, `pct`, `count`, `delta`, `day`, `shortDay`, `address`.
  Missing values read `n/a`, never a bare dash.
- Sentence case everywhere. No em dashes in user-facing text; use a comma, colon or full stop.
- No competitor names in chrome or captions. Naming a data source for attribution is fine.
- If a figure is scoped, estimated or partial, the caption or note says so.
- Our own count is the headline. Another source's figure sits beside it in a reconciliation note with the cause
  of the gap, never averaged in.

## 6. Charts (`components/Charts.tsx`)

Recharts 3 in the shadcn/ui chart recipes on the Datum tokens. Each chart fills its container's width; pass a
`height`. Series colours default to `--chart-1..8` in order. Tooltips use the shadcn indicator layout with
formatted values; stacked charts add a Total row. Animations are off so revalidated data does not re-animate.

| Component | Props | Use |
|---|---|---|
| `AreaChart` | `data, x='day', series, stacked, expand, unit, height, legend, curve, gradient, format` | Time series. `expand` stacks to 100%. |
| `LineChart` | `data, x, series, unit, height, legend, dots, curve, format` | Rates and ratios. |
| `BarChart` | `data, x, series, stacked, horizontal, unit, height, legend, labels, format, categoryWidth` | Categories. `horizontal` with `labels` for rankings. |
| `Donut` | `items, unit, height, centerLabel, legend, thickness, format` | Shares. Hover expands the sector and drives the centre readout. |
| `RadialChart` | `value, max, label, height, color, format` | One value against a maximum. |

`series` is `[{ key, label, color? }]`, `data` is rows (`{ day, supply, borrow }`), `items` is
`[{ name, value, color? }]`, `unit` is `usd`, `pct` or `count`.

For anything else, use the shadcn building blocks directly: `ChartContainer`, `ChartTooltip`,
`ChartTooltipContent`, `ChartLegend`, `ChartLegendContent` from `components/ui/chart.tsx`, with Recharts. Any
example on ui.shadcn.com/charts pastes in as is. Prefer Donut, Area and Bar over rows of horizontal bars.

## 7. Tables

`DataTable` with typed `cols`: `num` right-aligns with tabular figures, `hideSm` drops the column on phones,
`dim` mutes it, `render` formats the cell. `Asset` renders a symbol chip with a sub line; `Pill` with
`riskTone` colours utilisation and risk. Tables sit in a `Panel` with `flush`.

## 8. Data and status

`lib/data.ts` turns platform resources into the normalised shapes in `lib/types.ts`; pages never read raw
column names. The mapping lives in `datum.config.ts` (`resources`, `fields`, `fractions`). Without
`DATUM_API_KEY` the loader returns `lib/sample.ts`, deterministic and labelled on every page. `status` in the
config stays `draft` until `bin/datum check <slug>` prints READY; the page says so and is not embedded or shared.

## 9. Adding shadcn components

The template is initialised with shadcn (`components.json`, style base-nova, lucide icons). Add what a page
needs with `npx shadcn@latest add <name>`; it lands in `components/ui/` already themed. Do not add a second
component library.

## 10. Kit files versus dashboard files

`app/globals.css`, `components/*.tsx`, `components/ui/*`, `lib/format.ts`, `lib/types.ts` and `lib/datum.ts`
are kit files. Change them in this repository and copy them forward; do not fork them inside a dashboard.
`datum.config.ts`, `app/**/page.tsx`, `lib/data.ts` and `lib/sample.ts` are the dashboard's own.

## 11. Checklist before a page is shared

- [ ] The page header states the question and the one-line answer with an as-of date.
- [ ] Every chart and table sits in a `Panel` with a caption.
- [ ] Every number goes through a formatter; missing values read `n/a`.
- [ ] No hardcoded colours, fonts or sizes; no em dashes; sentence case.
- [ ] Checked in light, dark and at phone width; no horizontal scroll.
- [ ] `npm run typecheck` passes; `npm run build` passes.
- [ ] `bin/datum check <slug>` prints READY and `status` is `live`.
